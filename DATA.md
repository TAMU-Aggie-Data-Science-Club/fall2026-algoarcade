# Data

This file explains **Arcadia's** data situation. RL is different — the "data" is generated by the agent interacting with an environment. There's no external dataset.

> **`DATA.md` is tracked in git. The `data/` folder is not.** Training logs and model checkpoints are large and reproducible — they must never be committed. Clone the repo, then generate `data/` locally by running training.

## How to think about reproducibility (the actual "data" question)

- **Seed management is the whole game.** RL runs vary wildly across seeds. Every training script logs the seed. Every reported result is averaged over ≥3 seeds. Every claim is compared on the same seed set.
- **Config-driven runs.** All hyperparameters live in versioned config files. The commit hash of the config that produced a result is logged with the result.
- **Log everything to TensorBoard.** Rewards, losses, KL divergence (for PPO), replay-buffer stats (for DQN). Cheap; saves you when a run looks off.
- **Checkpoints in `data/`**, never in git. Include the checkpoint filename convention in [`DELIVERABLES.md`](DELIVERABLES.md).
- **Recorded episodes** for the writeup: use `gymnasium.wrappers.RecordVideo` to save short clips of trained agents.

## Local layout convention

```
data/
├── raw/          # (unused — RL generates its own data)
├── interim/      # replay buffers, rollout traces
└── processed/
    ├── runs/     # TensorBoard event files, one dir per (algo, env, seed)
    ├── ckpts/    # saved model weights
    └── videos/   # recorded gameplay for the writeup
```

Because `data/` isn't in git, the **training pipeline and configs** are what must be committed and reproducible — not the runs themselves.
